# Milestone 4 — Deploy the Wazuh Single-Node Stack

**Date:** 2026-09-27
**Status:** ✅ Complete

## Goal

Deploy the official Wazuh single-node Docker stack (Indexer, Manager,
Dashboard) at a pinned version, verify TLS certificates are generated
correctly, and confirm the dashboard is reachable.

## Environment

- Wazuh version: 4.9.0 (pinned via Git tag)
- Deployment method: Docker Compose (single-node)
- Host RAM visible to WSL: ~11 GiB
- Docker: 29.8.0, Compose v5.5.1

## Command

```bash
# 1. Clone Wazuh's official Docker repo at pinned version
cd ~
git clone https://github.com/wazuh/wazuh-docker.git -b v4.9.0
cd wazuh-docker/single-node

# 2. Generate TLS certificates
docker compose -f generate-indexer-certs.yml run --rm generator

# 3. Launch the stack
docker compose up -d

# 4. Verify
docker compose ps
docker compose logs --tail=15 wazuh.dashboard
```

## What I Learned

- **Wazuh's `single-node` stack is three containers, not one.**
  The Indexer (OpenSearch) stores events; the Manager processes rules
  and receives agent traffic; the Dashboard is the web UI. All three
  must be healthy for the UI to work.
- **Certificates are generated by a one-shot container**, not by hand.
  `generate-indexer-certs.yml` runs a container that writes the root CA
  plus per-component certs into `config/wazuh_indexer_ssl_certs/`.
- **First boot produces scary-looking errors that aren't.** The
  Dashboard logs show `[ResponseError]` and
  `[resource_already_exists_exception]` during its first minute. This
  is the dashboard racing the Indexer's startup and retrying — it
  resolves itself and does not affect functionality.
- **Pinning the Wazuh version via Git tag** (`-b v4.9.0`) matters.
  Cloning `main` would silently drift as upstream changes, making the
  deployment non-reproducible.

## Gotcha — Cert Generator Writes as root

Immediately after running the cert generator, attempting to read the
output directory failed:

```
$ ls -la config/wazuh_indexer_ssl_certs/
ls: cannot open directory 'config/wazuh_indexer_ssl_certs/': Permission denied
```

**Root cause:** the cert generator container runs as root (UID 0) and
writes files with mode `0400` into a directory with mode `0500`, owned
by `root:root`. Your normal user cannot even list the directory.

**Fix:**

```bash
sudo chmod 750 config/wazuh_indexer_ssl_certs/
sudo chown -R kelvi_f:kelvi_f config/wazuh_indexer_ssl_certs/
```

**Why this is safe:** `chmod 750` opens the directory for the owner
(you) while leaving the cert files themselves at mode `0400`. Docker
Compose maps these into the containers with the UID translation the
Wazuh services already handle.

**Verification:**

```bash
openssl x509 -in config/wazuh_indexer_ssl_certs/wazuh.indexer.pem -noout -subject -dates
```

Expected subject: `CN = wazuh.indexer`, valid for ~10 years.
